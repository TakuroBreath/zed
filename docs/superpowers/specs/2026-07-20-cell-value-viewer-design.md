# Просмотр и редактирование значения ячейки (JSON/text) — дизайн

**Статус:** одобрено (брейншторм 2026-07-20).
**Ветка:** `database-viewer`.
**Автор процесса:** субагент-исполнение, пользователь делегирует автономную реализацию (Rust не пишет сам).

## 1. Цель

В БД-панели значения `json`/`jsonb`/`text` часто длинные: в гриде видна только обрезанная строка, а нынешний мини-попап «View value» показывает значение сплошным текстом без форматирования. Нужен pgAdmin-подобный опыт: раскрыть значение в большом окне, увидеть отформатированный JSON с подсветкой, проверить валидность и при необходимости отредактировать и записать в базу.

## 2. Объём

**v1 (этот дизайн):**
- Большое модальное окно просмотра/редактирования значения одной ячейки со встроенным настоящим многострочным `Editor` Zed.
- Подсветка синтаксиса JSON, автоформатирование валидного JSON при открытии, переключатель Raw, живой индикатор валидности.
- Редактирование с записью через существующий буфер правок (Apply → буфер → существующий Save одной транзакцией).
- Read-only-режим для результатов произвольных SQL-запросов и нередактируемых таблиц.
- Две точки входа: пункт контекстного меню ячейки и кнопка «развернуть» в инлайн-редакторе.

**Не в v1:** поиск по тексту внутри окна; фолдинг; просмотр других форматов (XML, base64, hex); редактирование нескольких ячеек сразу; дифф «до/после».

**Не-цели:** менять способ выборки данных (в ячейках уже лежат полные строки — режется только отображение в гриде); прямой `UPDATE` из окна в обход буфера правок.

## 3. Точки входа

1. **Контекстное меню ячейки.** Существующий пункт «View value» открывает новое окно. Нынешний мини-попап `ValuePopover` удаляется вместе со своим состоянием (`value_popover`) и тестами — окно полностью его заменяет.
2. **Кнопка «развернуть» в инлайн-редакторе.** Двойной клик по ячейке, как и раньше, открывает однострочный инлайн-редактор; в нём появляется кнопка-иконка «развернуть», которая переносит текущий (возможно уже изменённый) текст поля в большое окно и закрывает инлайн-редактор без коммита. Работает и для существующих строк (`EditTarget::Existing`), и для insert-строк (`EditTarget::New`).

## 4. Окно

- Модалка воркспейса по паттерну `ConnectionModal` (`workspace::ModalView` + `toggle_modal`), крупная: ~60–70% ширины окна, высота с ограничением и внутренним скроллом редактора.
- Внутри — многострочный `Editor` Zed с моноширинным шрифтом. Если значение определено как JSON (см. §5), буферу назначается язык JSON из реестра языков → подсветка синтаксиса.
- **Шапка:** имя колонки + тип (`udt_name`/`data_type` из структуры, если известен; для кастомных запросов — без типа).
- **Панель под редактором:** индикатор валидности (§5), кнопки **Format**, **Raw** (переключатель), **Copy**, **Set NULL**, **Apply**, **Cancel**. В read-only-режиме (§7) Apply и Set NULL скрыты.
- Escape / клик мимо окна — закрытие без записи (как Cancel).

## 5. JSON-логика

- **Определение JSON:** в режиме просмотра таблицы — тип колонки `json`/`jsonb` из загруженной структуры; в режиме произвольного SQL-запроса (типов нет) — значение считается JSON, если успешно парсится `serde_json` в объект или массив (голые числа/строки не считаются, чтобы не подсвечивать обычные числовые колонки как JSON).
- **Автоформат при открытии:** валидный JSON показывается сразу pretty-print'нутым (`serde_json::to_string_pretty`). Кнопка **Raw** возвращает исходную строку; повторное нажатие / **Format** — обратно к форматированному виду.
- **Индикатор валидности:** обновляется по мере набора: «Valid JSON» либо «Invalid JSON: строка N: <ошибка serde_json>». Для колонок, не определённых как JSON, индикатор не показывается, но кнопка **Format** доступна, если текущий текст парсится.
- **Невалидный JSON не блокирует Apply:** колонка может быть обычным `text`, а для `jsonb` ошибку вернёт Postgres при Save — она отобразится в существующей плашке ошибки сохранения.

## 6. Запись — через существующий буфер правок

- **Apply** не делает прямой `UPDATE`: он кладёт текст в тот же буфер правок, что и коммит инлайн-редактора (`set_cell_value` / `set_new_cell_value` по `EditTarget`), после чего панель становится «грязной» и реальная запись выполняется существующей кнопкой Save одной транзакцией. Один путь записи, никакой новой логики транзакций.
- **Проверка «без изменений»:** базой сравнения служит **исходное значение ячейки** (не текст на момент открытия окна — при входе через кнопку «развернуть» туда мог попасть уже изменённый текст инлайн-редактора, и он должен буферизоваться). Если текст редактора совпадает с исходным значением ячейки в любой из двух форм — raw или его pretty-print — Apply ничего не буферизует и просто закрывает окно. Следствие: если пользователь отредактировал форматированный текст, в базу уходит форматированный вид — для `jsonb` это семантически то же самое (Postgres нормализует), для `json`/`text` меняются только пробелы, что считается приемлемым (поведение как в pgAdmin).
- **Set NULL** буферизует NULL тем же путём, что и в инлайн-редакторе (`set_cell_null` / `set_new_cell_null`), и закрывает окно.
- Окно привязывается к стабильному ключу строки (`RowKey`/`InsertId`), захваченному при открытии, — как инлайн-редактор, чтобы Apply лёг в нужную строку, даже если отображение изменилось. Если на момент Apply редактирование стало недоступно (`!editable()`), значение не буферизуется — та же защита, что у `commit_cell_edit_inner`.

## 7. Read-only-режим

Для результатов произвольных SQL-запросов и нередактируемых таблиц (нет первичного ключа, `editable() == false`) окно открывается только для чтения: `Editor` в read-only, доступны подсветка, Format/Raw, Copy; Apply и Set NULL скрыты. Это покрывает исходный сценарий «удобно посмотреть значение» везде, где есть грид.

## 8. Крайние случаи

- **NULL-ячейка:** окно открывается с пустым редактором и пометкой «NULL» в шапке; любой введённый текст по Apply буферизуется как значение (перестаёт быть NULL) — как у инлайн-редактора.
- **Пустая строка vs NULL:** различаются так же, как в инлайн-редакторе (пустое поле при исходном NULL — «без изменений»).
- **Save в процессе (`is_saving()`):** Apply — no-op, как у остальных операций записи.
- **Очень большие значения:** редактор скроллится; никакого дополнительного обрезания не вводим.

## 9. Тестирование

GPUI-тесты в стиле существующих тестов `table_data_view.rs`:
- открытие окна из контекстного меню и из инлайн-редактора (текст инлайн-поля переносится, инлайн закрывается);
- автоформат валидного JSON при открытии и переключатель Raw;
- определение JSON по типу колонки (таблица) и по парсу (кастомный запрос); голое число в кастомном запросе не считается JSON;
- индикатор валидности на валидном/невалидном тексте;
- Apply буферизует изменённое значение и не буферизует неизменённое (в обеих формах);
- Set NULL буферизует NULL;
- read-only-режим для кастомного запроса: Apply/Set NULL отсутствуют;
- NULL-ячейка открывается пустой с пометкой NULL.
